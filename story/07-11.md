シグナリングサーバー自体は `npm run signaling:dev` で起動する。WebSocket の中継は動く。ただしクライアント側で WebRTC 接続を張るコードがまだないので、ブラウザ間で投稿が伝播するのは Story 7-8 が終わってから。

---

### Phase 2 残りの概要

**Story 7: WebRTC 接続確立**

シグナリングで得たピアリストに対して RTCPeerConnection を生成し、SDP/ICE を交換して DataChannel を確立する。ConnectToPeerUseCase 的なものが要る。STUN で NAT 越え、TURN なし。ブラウザ API に依存しないインターフェースを切って、シードノードでも同じコードが動くようにする。ここが一番重い。

**Story 8: WebRTCGateway**

IGossipMessageGateway の WebRTC 実装。BroadcastChannelGateway を差し替える。複数の DataChannel に対してファンアウト（最大5）で送信、各 DataChannel の onmessage を集約して受信。DataChannelMessage（gossip | heartbeat）のパース。ここまででPoC成立。

**Story 9: ピア数表示**

接続中の直接ピア数を UI に表示。HeartbeatTracker の dead 判定で切断検知。近似値で十分。

**Story 10: シードノード**

Node.js ヘッドレスピア。core をそのまま使い、Adapter だけ差し替え。IndexedDB → ファイル or SQLite。シグナリングサーバーと同居可能。

**Story 11: 板・スレ拡張基盤**

板の一覧を定数管理。スレ作成の UI は作らないがドメインでは可能にしておく。PoC 後。
