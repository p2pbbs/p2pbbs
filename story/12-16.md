# Phase 3 チケット

## [Story 12] シードノード（ヘッドレスピア）

### ユーザーストーリー

nch ネットワークの安定性のために、長時間稼働するヘッドレスノードが過去の投稿を保持し、新規参加者がデータを取得できる。

### 受け入れ条件

- [ ] Node.js でブラウザなしに動作する
- [ ] core（domain, usecase, controller）をブラウザ版と共有する
- [ ] IPeerConnectionFactory の Node.js 実装（node-datachannel 等）
- [ ] IndexedDB の代わりにファイル or SQLite で永続化
- [ ] シグナリングサーバーに接続してピアと WebRTC 接続を確立する
- [ ] gossip で投稿を受信・保存・再ファンアウトする
- [ ] 他のピアと対等。管理権限や特権はない
- [ ] シグナリングサーバーと同居可能

### 設計メモ

- Adapter 層のみ差し替え。UseCase / Domain は変更なし
- IPeerConnection / IDataChannel インターフェースが Story 7 で定義済み
- IPostStore の永続化実装を差し替える（IndexedDBPostStore → FilePostStore or SQLitePostStore）

## [Story 14] ロード表示

### ユーザーストーリー

掲示板を開いたユーザーとして、接続中や過去ログ読み込み中の状態がわかる。

### 受け入れ条件

- [ ] シグナリングサーバーへの接続中に「ネットワークに接続中...」が表示される
- [ ] state 受信待ちの間に「過去ログを取得中...」が表示される
- [ ] state 受信完了 + 投稿フォーム有効化で通常表示に切り替わる
- [ ] ピアが 0 の状態で「他のユーザーを待っています」が表示される
- [ ] シグナリングにも繋がらない + ピア 0 で「ネットワークに接続できません」が表示される
- [ ] 操作をブロックしない。ステータス表示のみ
